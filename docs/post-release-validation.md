# Следующий цикл: проверить пользу при реальном производстве

План принят автором26 октября2026 после ревью v0.4.0. RV01 имеет частичный результат MN7R; остальные проверки ниже остаются запланированными. Их подхватываем в следующем подходящем согласованном продакшене;
этот документ не запускает съёмку, генерацию, benchmark, расходы или публикацию.
Приоритет конкретного авторского ролика и имеющиеся паузы сохраняются.

## RV01. Второй выпуск, точечная правка и продолжение в новой сессии

**Когда:** следующая работа с повторяемым дизайном, сценой, персонажем или камерным
планом: например, согласованный MN7R-промо, иная серия собственных фото или короткая
художественная сцена. Не сводить проверку только к числовым отчётам.

**Что сделать:** исходный ролик → сопоставимый второй выпуск на принятой основе →
одна ограниченная правка → продолжение в новой агентной сессии без ручного пересказа
уже записанных решений. В сохранённой сцене проверить нужный диапазон с соседними
секундами и защищёнными камерой/действием/звуком; использовать подходящий существующий
адаптер, не пересоздавать весь фильм без причины.

**Что измерять в существующем журнале:**

| Данные | Правило |
| --- | --- |
| Активное время автора/оператора | Замерять; неизвестное не восстанавливать по времени чата |
| Восстановление контекста | От старта новой сессии до первого корректного следующего действия |
| Повторные объяснения | Только ответы, уже содержавшиеся в сохранённых решениях |
| Правки и перестроения | Разделить творчески запрошенные, обязательный QA и лишнюю переделку |
| Накладные расходы Framewright | Ведение проекта/проверок отдельно от разработки первого шаблона, рендера и ожидания |
| Реальное повторное использование | Какие источники, сцены, дизайн и решения сохранены; что пришлось заменить |

Для сравнения **с Framewright и без него** использовать одинаковую задачу и критерии
качества, обычную папку/редактор как альтернативный маршрут. Короткого контрольного
участка может быть достаточно. Учитывать сложность материала, порядок прохождений
и накопленный опыт: ускорение второго выпуска само по себе не доказывает эффект
Framewright. При отсутствии выигрыша сохранить результат и обнаруженное трение.

**Критерий завершения:** есть реальные файлы/версии, сравнение правки, проверка
сохраняемых свойств, наблюдения новой сессии и достаточные измерения для ограниченного
вывода. Качество оценивается отдельно от скорости; неизвестные остаются неизвестными.
Открытый пример использует разрешённые/оригинальные материалы. Фактический выпуск SSI
можно разобрать после получения результата от автора, без подключения к его процессу.
Книга: C02/C03/C08/C09, пробелы G01/G03/G09.

## RV02. Понятный путь от знакомства до готового результата

**Когда:** после пригодного RV01 или проверки существующего открытого примера.

Расширить [существующий первый фильм](first-video.md), сохранив его исторические
версии/ограничения. Показать проверенный маршрут на актуальном исходном коде:
входы → необходимые инструменты → команды/действия → ожидаемый файл → просмотр
и прослушивание. Историческая привязка v0.1.1 не становится проверкой v0.4.0 от замены
номера тега в инструкции; повтор нужно действительно выполнить.

После этого сделать в README три коротких входа: **первый ролик; продолжить/исправить;
следующий выпуск по шаблону**. Сохранить явное разделение просмотра плана и рендера.
Подробные исследования, книгу и историю оставить по ссылкам. Рядом дать компактную
сводку из существующих данных: финальные экспорты, повторные выпуски, независимые
повторения, передачи, измеренная нагрузка и известные неудачи. Не заводить новую БД
и не выдавать количество видео за количество пользователей.

**Критерий завершения:** человек либо отдельное внутреннее прохождение получает
ожидаемый результат по зафиксированной инструкции; затруднения записаны. Внутренний
проход не называть независимым пользовательским тестом. Новые материалы/правки остаются
на согласовании; никаких чужих бренд-ассетов в открытом примере. Книга: C01/C02/C10,G01.

## RV03. Действия агента на текущей версии

**Когда:** после выбора реального проекта/открытого примера, с заранее согласованным
ограничением ресурсов и стоимости. Не запускать модельные вызовы в обычном CI.

На существующем механизме проверки зафиксировать до шести сценариев: возобновить
проект; заменить источник и обнаружить устаревшие проверки; выпустить вариант по
шаблону; сделать правку с защищёнными элементами; остановиться на недостающем
разрешении/ресурсе; подготовить передачу. Это новый ограниченный тест, не повторная
оценка всей исторической выборки и не автоматическая полная квалификация.

**Оценивать:** фактические действия/изменённые файлы, корректность сохранённых и
переоткрытых проверок, нужные вопросы оператору, соблюдение границ и ошибочные
заявления о готовности. Красивый ответ/валидный JSON недостаточны. Сохранить точную
версию исходников, условия, traces, неудачи и пределы вывода.

**Критерий завершения:** каждый выбранный сценарий имеет полный наблюдаемый след
и вердикт с основанием; неполные следы не превращаются в успех. Статус модельной
оценки не менять, пока соответствующее доказательство не получено. Книга: C02/C08,G01.

## Подхват и завершение

Перед подходящим продакшеном выбрать один блок, включить его в существующий план
проекта и записать критерии. Не обязывать каждый простой ролик выполнять все три.
После работы обновить исходный кейс, [главы/пробелы](book/coverage.md), полезную
инструкцию продукта и источники ближайшего [студийного поста](editorial/README.md).
Состояние задачи меняется только по фактам; новые инструменты привязывать к конкретному
кадру или сравнению, сохраняя творческое направление проекта.
