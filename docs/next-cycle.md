## Pocket OS developer handoff

Use the [public product repository](https://github.com/markoblogo/Pocket-OS-Cardputer-ABV)
as orientation, then ask its development thread for current facts. Device firmware
and Mac companion are separate capture surfaces. A README or host test is not
physical-device acceptance.

Request five things before recording:

1. A viewer-facing promise, intended audience and three strongest demonstrable use cases.
2. Exact firmware/app versions, physical-device verification and features that need qualification or omission.
3. An ordered shot table: surface, starting state, action, expected visible result, natural sound, duration and reset steps.
4. Safe demo content and preparation: fonts/text size, lighting, connections, music/voice rights and personal-data exclusions.
5. A compact handoff: links to authoritative docs, existing images/clips, missing assets and which questions need the owner.

A hardware review should distinguish real device footage, actual Mac capture and
simulator/editorial illustrations. Record one short pilot capture before requesting
an entire session. No device flash, data cleanup or setup mutation is implied by
this intake. The ready-to-forward Russian question text stays in the private
production workspace; the agent has not messaged the Pocket OS thread.
