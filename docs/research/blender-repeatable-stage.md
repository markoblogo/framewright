# Blender repeatable stage — retained approach and separate project watch

Initial retention: 2026-10-26, documentation/reference review only. Later that day,
the owner authorised an independent internal Blender trial, now [technically completed](../experiments/blender-shot-replay.md)
with a portable official build and original fixture. This did not use the unavailable
reference project's code/build. Artistic/production qualification remains pending.

## Reference project: watch only

[Jake Denham — I Rebuilt 3ds Max With AI](https://youtu.be/74TsKdNWEaA)
shows a custom Blender-based environment with Max-like hotkeys, quad menu and
modifier workflow, scene tabs and integrated AI/asset tools. The author's description
and selected demonstration segments were inspected; a complete transcript was not
retrieved. The author explicitly describes a personal project with no download or
sale. Retain under observation until an actual build and usage terms are available;
recheck platform support, provenance and licence before any later test.

The reported fourfold improvement concerns cold application startup on the author's
PC, not render speed. His 23/23 legacy .max scenes are a bounded author claim, not
general format fidelity or compatibility with third-party Max plugins. Existing
Windows-only candidates do not become Mac-compatible through this demonstration.
No released source, open-source licence or current Mac build is established.

## Independent approach: bounded test and production follow-up

**Scene → action → two cameras → lighting edit → render again without rebuilding
the scene.** This test can use standard Blender independently of the unavailable
reference project. A full custom application/interface is premature and out of scope.

Before execution choose one original or cleared scene/character and a short action;
confirm available Blender build, renderer, source rights, resources and budget.
Retain the editable .blend scene, asset origins, action, camera transforms, light
settings, frame range, frame rate, seed where applicable and output revisions.

Render the same action from two cameras. Change only an identified light parameter,
save and render the same range again. Reopen the scene to check that cameras,
geometry, materials and animation remain usable without regeneration/reconstruction.
Compare composition, animation/contact continuity, lighting, picture quality, time
and manual effort. Preserve intended lighting differences and document unintended
changes. Encoded playback and owner review remain distinct from structural checks.

Success means a reusable editable setup supporting a bounded lighting revision and
repeatable camera coverage. It does not qualify an entire custom editor, .max import,
Max plugins, AI image/video generation, cloud services, or natural facial animation.
Any later generative finishing pass is a separate continuity/rights/cost test.
Review Blender/add-on licences and independent asset/service rights before use;
do not infer permission to copy the author's implementation from a public video.
