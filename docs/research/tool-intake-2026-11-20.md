## 1. FilmCraft — priority candidate for editable agent-driven finishing

[Repository](https://github.com/storytold/filmcraft),[agent protocol](https://github.com/storytold/filmcraft/blob/main/docs/agents.md),[project format](https://github.com/storytold/filmcraft/blob/main/docs/project-files.md),[manifest](https://github.com/storytold/filmcraft/blob/main/Cargo.toml),[MIT licence](https://github.com/storytold/filmcraft/blob/main/LICENSE-MIT).

Upstream documents a Rust nonlinear editor with native Mac and web builds,CLI/MCP control,headless engine and bridge to its visible editor. The manifest reports0.20.1;this is a main-branch source version,not a locally installed or verified release. JSON projects retain media references. README documents OTIO/FCP interchange and H.264/AAC export,but labels the product alpha with real-media/performance limitations. Licence declared MIT OR Apache-2.0;dependencies and footage separate. No readiness percentage is treated as our benchmark.

**Our inference:** strong fit for keeping an editable timeline behind accepted review/delivery,especially lessons and bounded corrections. Existing FFmpeg,HyperFrames,OpenMotion and Kdenlive evidence remains valid;this is an optional alternative,not a studio rewrite or character-motion solution.

**FILMCRAFT-01 proposed:**15–20s owned fixture:three clips,two audio tracks,title/caption. Import and trim;save;close/reopen in a fresh process;change one title and one cut through the command interface;export1080p and independently decode/check duration,sync,fonts and frame samples. Compare untouched spans and retained project structure. Pin actual binary/revision first. Record hands-on time and failures;stop on unreliable reopen/export. No large course migration. MCP docs expose general user filesystem authority,so no global connection during intake.

## 3. UltraTex — research reserve,not an executable local route

[Paper](https://arxiv.org/abs/2611.24941),[project](https://ultratex.vercel.app/),[model card](https://huggingface.co/Jingzhi03/UltraTex).

Research predicts physically based texture channels for assets:albedo,metallic/roughness and related normal processing,with material knowledge and lighting alignment. It concerns surface appearance under changing illumination,not mesh reconstruction or character animation. Potential fit:making our3D props look less uniformly plastic.

The project explicitly says its code uses Meshy’s internal framework and open-sourcing awaits internal approval. The model card lists weights/components but does not specify their licence;project figures carryCC BY-NC-SA4.0. No ready inference provider,Mac execution path or measured resource budget was established. Meshy7/8K commercial offering is a separately gated service,not proof the paper is locally runnable.

**ULTRATEX-01 watch:** reconsider when runnable code,model terms and suitable resources are available. A future owned-mesh comparison should relight the same geometry under two lights and inspect seams/material consistency,without mistaking prettier lighting for improved maps. No weight download now. Use existing authored PBR materials in the meantime.
