## Fit for Framewright

This is a collection of agent instructions, examples and some asset-QA helpers, with an engine/task dispatcher. It is not a hosted renderer, a collection of animation clips, a music/voice generator or an automatic video editor. Its described Codex compatibility is not a local installation test. Engine-specific snippets need the actual project's locked release, not automatic migration to the author's stated baseline.

## Integration proposal

Keep Framewright's source/brief/evidence and publication workflow as the outer controller. Load only the engine/task references selected for one shot; do not install the entire pack or replace the router. Film-oriented requirements remain explicit: actor action, camera/framing, lighting, deterministic time/seed, cue timing, capture and encoded QA. Steam publishing, multiplayer, economy and game-progression skills are not current film priorities.

First proposed trial: an owner-approved 15–20s two-shot miniature. A licensed rigged character walks, stops, turns and interacts with one lit prop; shot 2 preserves position, light direction and action continuity. Compare with our procedural traveler on the same shot requirements. Check repeated seeks to identical times, foot sliding/contact and occlusion, transitions across the cut, shadow/crop and audio sync, final decode and owner viewing/listening. Retain model/clip rights and failures. No provider generation, world download, engine installation or trial is authorised by this research entry.
