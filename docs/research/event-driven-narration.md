# Event-driven narration — queued method trial

Owner-selected on 2026-10-26. Reference reviewed; no production trial or speech
generation performed. This is a method candidate, not an Embark runtime provider.

## Reference and boundary

[THE FINALS developer video](https://www.youtube.com/watch?v=eA9_Q6d2H-g)
and [official PRIME TIME notes](https://www.reachthefinals.com/patchnotes/12-00)
describe Dynamic Commentary: selected gameplay events trigger contextual lines
mentioning participants, mixed with existing prepared commentary. Initial beta
scope limits the event types and frequency. Video transcript and official notes
were inspected. These materials do not provide a separate reusable tool/API or
demonstrate general-purpose video understanding. No voice, recordings or code from
the game are to be copied or treated as cleared production assets.

## Owner-selected first trial

**30–45s recording → three verified events → one voice.** Check commentary accuracy,
timing, naturalness and absence of unnecessary chatter. Choose an authorised clip
and a cleared voice before execution. Start after capture, not as a live service.

Use the existing project journal and scene/edit timeline: record event time,
observed action and evidence, proposed short line, selected speech file and actual
placement. Engine event logs and editorially verified observations are distinct;
an inferred event from third-party footage needs verification before narration.
Do not infer unseen actions, names, motives or outcomes.

Measure speech duration before placement; use pauses or omit a line when it cannot
fit without obscuring dialogue or important source sound. Review all three lines
against the picture, pronunciation, event order and actual playback timing. Record
factual/timing defects separately from owner preference about delivery and verbosity.
Retain the source/output revisions, event-to-line mapping, voice/model settings,
manual corrections, processing time and any actual cost. A later live version
would need a separate latency/stale-event test; this trial does not qualify it.

Potential applications: gameplay reviews, guided walks, product demonstrations and
interactive stories. Existing TTS may be chosen after availability/rights checks;
no new API connection, cloned Embark voice, spend, upload or publication is authorised
by queue retention. No executable provider or duplicate project system is added.
