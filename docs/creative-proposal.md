# Creative proposal and recommendations from past cases

Owner decision, 10 November 2026. Apply to the next selected fiction-book film,
then retain useful practice for later fitting productions. Supports M1/R02,
M2/RV01, M3–M5/R05/R07 and R09. This extends the existing proposal, method
records and revision journal. It is an agent-and-human planning procedure;
`intake.py brief` still supplies bounded routes and broad proposed scene purposes,
not an implemented director or automatic creative recommender.

## One compact proposal before reference frames and the pilot

Read the selected text and supplied art first. Confirm the book/episode, audience,
language, length, aspects and permitted adaptation. Unselected material stays
unselected; do not invent a plot from a title or inherit another film's language.

Prepare one page in the private production folder, using the existing brief and
scene plan rather than a second project database:

| Question | Decision to show |
| --- | --- |
| Viewer result | What should the viewer understand or feel by the end? |
| Dramatic hook | What image, conflict or unanswered question holds attention? |
| Treatment | Chosen visual language, rhythm, sound role and reason it fits this book. |
| Real alternatives | One to three meaningfully different treatments only where useful; explain the choice and tradeoff. A palette swap or renderer change alone is not another treatment. |
| Economy | What can be removed without losing meaning? What must survive from the book and its illustrations? |
| Full-film action | For each beat: what changes in action, viewpoint, composition or sound, and why? An intentional still hold needs a reason; a moving opening does not validate the rest of the film. |
| Risk and pilot | Which story, continuity, contact, timing or readability risk matters most; which shortest useful linked excerpt will test it; what would make us revise or stop? |

Do not add arbitrary cuts or motion to a deliberately quiet scene. Do not apply a
fixed seconds-per-shot rule across unrelated work. Plan the full arc before the
pilot so one animated image does not accidentally become the whole film.

## Recommend from evidence, not catalogue size

Select up to three relevant recommendations from existing case records. Fewer is
fine. These are conditional suggestions for a new film, not preselected techniques.
For each recommendation retain:

```text
Current scene need / viewer-facing result:
Source case / exact recipe or evidence link / observed scope:
Suggested technique / why it fits here / when to avoid it:
Known defect / anticipated correction / simpler fallback:
Measured correction effort and its scope, or UNKNOWN:
Selected / declined / deferred, with reason and next pilot check:
```

Do not call a shorter exported clip, existing credits or a faster render a measured
saving in active production time. Record the actual setup, work, waiting/render
and correction observations separately; missing values stay UNKNOWN. Rights,
provider access and current-machine fit require their own selected-route checks.

## One real correction and a useful closeout

When an actual defect appears, use [the existing revision contract](../skills/video-production-router/references/revisions.md):
interval, defect, desired change and protected properties; retain original and
candidate, compare with neighbouring context, review picture/sound, then select.
Do not invent a defect or rerender accepted work merely to tick an experiment box.

Check constraint compatibility before promising preservation. Slower delivery,
unchanged words and a fixed short interval may conflict; propose shorter copy,
existing pauses or an explicitly agreed timing change. The
[results-film voice replacement](productions/centre-crop-results-film.md) preserved
all accepted picture packets; that scoped case is not a guarantee for any edit.

At closeout, record which case-informed choices were selected/declined, whether
those risks appeared, actual revisions and repeated instructions, measured effort
or UNKNOWN, and the reusable lesson. Keep technical proof, creative/listening
acceptance, rights and later audience results separate. A first application does
not establish reduced labour or independent-user success.
