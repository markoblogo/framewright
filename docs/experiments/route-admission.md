# ROUTE-01: selected route → checked local action

28 October 2026. Owner authorised connecting selected proposals to source, environment,
cost/limit and expected-file admission without a new production. This is a bounded
local adapter extension, not a whole-route renderer or external provider dispatcher.
[Commands and limits](../../skills/video-production-router/references/route-admission.md).
[Sanitized receipt](../../experiments/2026-10-28/evidence/route-admission.json).

## Implemented behaviour

An actual `intake.py routes` comparison, chosen route/stage, requirement manifest,
source, task/output identities and all supported arguments are explicitly bound in
a retained selection. The same project stores a task-to-selection mapping and its
integrity hash. The selection pins its sources and current implementation/cost
classification; intake suggestions alone do not execute anything or grant acceptance.

Every bound executor invocation checks that binding automatically. Under the existing
locks it validates current bytes, invocation, planned-task state, dependencies/waits,
fixed local program versions, declared OS/architecture/total memory/disk/model/manual
requirements, optional current available memory, source-use rights, known zero local
software fee/unit and actual timed media/interval. It records admission evidence,
then persists the existing durable intent before dispatch. An unmet or unknown
required condition stops before the worker and creates no dispatch intent.

The first adapter maps the selected local FFmpeg stage only to `local-media-review`
or `review-clip`. It does not silently run HyperFrames, quota generation, a paid API
or a complete picture/voice/finishing recipe. Legacy unbound manual commands remain
supported; bound tasks cannot opt out by dropping a command flag. Revision-comparison
and other adapters need their own later bound contracts.

Expected artifact identity/kind/format and byte allowance are part of the selection.
After a worker completes, report source/schema or MP4 proxy dimensions/rate/container/
interval and byte bounds are checked before retention. Excess size/invalid output
records failure, not acceptance. Worker timeout applies to the owned process group;
output allowance is a postcondition, not a hard disk quota or RAM cap. Preflight
snapshots do not prove the next arbitrary model/render will fit.

## Checks and learned correction

Behaviour-first CLI controls cover accepted selection/execution with review pending,
changed source/arguments, wrong host, unknown fee/rights, incompatible route stage,
invalid limits/output binding, contract repinning, unknown/unmet available RAM,
output-size failure, existing-output redispatch, actual temporary-volume shortage,
the public preparation script and a real synthetic video proxy.
Both worker formats are actually generated/decoded from original synthetic media.

An initial failed assertion found that blocked unknown-cost evidence still printed
zero for the local fee. It was corrected to null; admission remains blocked. A second
control found that read-only admission alone could still appear ready after an output
was produced, although the executor already refused overwrite. Admission now checks
occupation/type/required-output mapping too, and directs review instead of redispatch.
Initial failures are retained privately; this is software behaviour, not a model score.

A full regression also exposed system-disk exhaustion: tests failed creating default
temporary files while the external Work volume had354GiB free. No user data or
foreign caches were removed. Subsequent checks use an explicit external TMPDIR.
Admission now observes that actual temporary volume as well as the project volume;
its floor is the declared disk requirement/output allowance, not an invented peak
space guarantee. The storage incident and partial failed run remain distinct from
software verdicts. First public-example preparation also stopped before completion;
its generic subprocess error did not establish the cause. Error reporting was improved
and a clean complete walkthrough must be retained separately.

The original-fixture walkthrough prepares a private project from the public script,
checks it read-only, then explicitly executes one admitted local inspection. Its
result stays review_pending and its produced output is not automatically accepted.
No supplied user production footage, cloud transfer, paid/model call, upload or new
release is needed. Cost ledger context remains separate from provider enforcement.

## Remaining gates

- Bind further existing adapters one at a time, beginning with a useful controlled
  render, with executable/settings/output/resource evidence for that exact workload.
- Paid/external execution still needs budget reservations, actual authority, provider
  job/receipt reconciliation and ambiguous-outcome tests. No such dispatcher exists.
- Run the complete first-film/fresh-session/user-effort checks separately; a synthetic
  silent source is not a full film, independent user test or demonstrated time saving.
- Use a coherent original YouTube-suitable production when creative/runtime evidence
  requires it; public publication remains a separate action.
