## Service and capture lessons

A generic rhythm-game reviewer called the moving camera static and read the physical B marker as a button. Downloaded footage showed movement; the final build removed the lettering to satisfy the blocking no-UI finding. The remaining rhythm/score advice does not redefine the owner's intentionally endless game.

A first portrait watch reached an early zero clock during query seek. Initialising from the query before asynchronous scene readiness fixed that path. A versioned JavaScript filename prevents the server's confirmed one-hour cache from returning earlier code. Final native controls and revision-bound checks were repeated.

Two scenario observation windows describe the same existing walk, not invented levels. The service required distinct scenario/look/episode records; an inferred approval was refused and not recorded. Only the owner's later explicit answers populated those records. A valid publication receipt and public HTTP200/title/ID checks establish the game publication; the videos retain separate owner-report links.

The Codex connector OAuth metadata endpoint failed; the owner's already-configured local connection worked. Credentials and signed provider output URLs were not copied into evidence. Other engines, arbitrary worlds, all mobile devices and a general autonomous production pipeline remain unqualified.
