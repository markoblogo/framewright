## What was actually tested

[Three-Live](https://github.com/google/three-live) npm **1.4.0**, archive integrity verified, extracted externally without install scripts. Its JavaScript authoring types and `sceneToGLB` API exported an original scene. This is not a test of the Rust/native sandbox compiler, security isolation or an LLM service.

A five-mesh fixture exported and reopened with independent three.js **0.185.1 GLTFLoader**: five objects, colour/opacity values and animated positions at 0/2/3.5 seconds checked. The full Night Line scene then exported **192 meshes, 17 materials, three transform tracks and a 24-second animation**. The tram translates; two doors slide. It is an authored bidirectional shuttle cycle, not a physics simulation or character-acting trial.

A real browser download was opened on a separate independent viewer page. The downloaded GLB and the package GLB match the final export hash. Full-scene loader checks and screenshots bind to that export; selected lamp/planter base bounds were corrected before handoff and checked against the street surface. No general all-object contact qualification is inferred.

The miniature, materials and animation are original. The cinematic viewer supplies its own lighting, environment, floor, camera and post-processing. Basic material/transform portability is demonstrated for this asset; identical appearance everywhere, arbitrary effects, USDZ, AR and native/mobile devices remain untested. Three-Live is not an officially supported Google product.

## Capture failures and retained boundaries

The native Three-Live preview emitted an abort event without blocking the download. An iframe file handoff failed; separate-page file opening succeeded. Playwright's video compositor recorded blank/grey WebGL content even when screenshots were valid. Real timed Chrome screenshot capture during actual download/open actions replaced that recording; timestamps are retained. These source inserts have measured capture intervals around 10–12 fps and are normalised into the 30 fps film. Paused video seeking could also return a stale source image, so the compositor reads original captured JPEGs directly. Loading waits are cut, not represented as a faster export benchmark. The screens are explicitly a local test harness, not an invented official application UI. Failures are capture/integration findings, not proof that GLB export failed or that all other capture stacks fail.
