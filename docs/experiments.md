# Grow the lab without growing unsupported claims

Add a tool when there is a concrete task or comparison to investigate; a bookmark
alone may remain a candidate. Do not install or launch everything in the catalogue.

1. Record upstream URL/revision/licence and the narrow question. Identify paid calls,
   account access, downloads, asset rights and external side effects before running.
2. Prefer an authorised ABVX product with source facts and reusable assets. Choose
   success criteria before rendering: visual correctness, intelligible narration,
   sound timing/levels, delivery format. Do not invent numeric performance evidence.
3. Work in an isolated folder on Work. Retain the brief, timeline, commands/tool
   versions, failures, QA and final hashes. Keep media/models out of this repository.
4. Write an experiment record. Treat technical pass, user preference, listening,
   publication and audience performance as independent facts. Unknown stays unknown.
5. Update tested_scope only for demonstrated capability. Commit concise evidence
   and attribution. Update router scenarios when a new tool changes routing choices.

For composite workflows, record each tool's role and the artifact contract between
steps. Check the final assembled file; standalone success does not qualify a new
combination. Keep native failures visible even when another tool supplies the
requested deliverable. See [tool chains](../skills/video-production-router/references/tool-chains.md).

Catalogue states: candidate, prototype, tested_for_scope. They are scope labels,
not a ranking. The legacy catalogue remains structural_only. The separate
router-qualification.json record binds an actual current-source planning assessment
to its complete packet: model_checked_planning_scope requires all criteria to pass;
evaluated_with_gaps retains explicit failures without promotion. Separate actor and
grader contexts of one model family are not third-party certification. A schema
check does not evaluate a model. Do not claim comparative efficiency without a
fair comparison of time/cost/quality on the same task.

When evaluating routing later, use references/scenarios.json from the skill in a
read-only isolated task with no actual rendering, installing or publishing. Record
model/version/date and inspect decisions and actions against required/forbidden
behaviour. Freeze genuinely unseen cases before actor execution; do not relabel
exposed development requests as held-out. Include supplied source text in grading
and preserve incomplete-context or disputed grade attempts separately. The offline
validator never launches a model.

## Records across dates

Create `experiments/YYYY-MM-DD/outputs.json`; the validator discovers all dated
folders and rejects duplicate experiment IDs across them. The public contract is
[outputs.schema.json](../schemas/outputs.schema.json). Its small dependency-free
checker supports only the declared keywords and fails closed on new assertions.
Use an external full JSON Schema implementation for other schemas.

`evidence_checks` holds literal markers required in that record's evidence file.
Keep case-specific checks in data rather than adding experiment IDs to Python.
Top-level output, optional native export and PNG thumbnail retain independent hashes.
Local media verification is optional and requires the operator's retained artifacts;
it is not public reproducibility. The open source reference route is separate from
private author-project archives. New arbitrary attachment types need a schema and
validator change; do not imply that every nested metadata object is an artifact.

When decision sources change without a new complete model evaluation, record
`not_evaluated_current_source`, the prior `evaluated_status`, immutable packet and
current source hashes. Historical scores remain attached to their old source;
targeted deterministic tests do not promote current agent behaviour. The checker
continues checking archived actor/snapshot hashes and current file drift separately.
