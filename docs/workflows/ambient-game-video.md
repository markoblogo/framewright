# Use a game as a long ambient video source

Use this when the requested output is background viewing rather than a gameplay review. [Möbius Walk](../experiments/dream-walk.md) is the scoped test: Babylon.js canvas recording and a two-minute cycle extended to twenty minutes. A generated clip montage remains a different source type.

1. Agree the viewing mode: freely played game, scripted/autoplay capture or a filming-only camera path. Label it. An endless walk need not acquire a score, hazards or a forced ending just to resemble a rhythm game.
2. Retain the actual game/site revision, controls, engine/library version and source assets. Pin code/texture/video/audio separately. Use a unique script filename on re-host when the platform caches assets. Do not update a published game for a shot without task authorisation.
3. Test native start, pause/resume, mute/unmute, seek and autoplay, measuring actual audio output. Inspect every promised orientation and wait for real scene readiness. A moving numerical clock is insufficient proof of visible movement.
4. Record the real canvas without UI. For loops, choose a complete geometric/camera period and close independently animated phases deliberately. A recording-only canonical pass must be disclosed; it is not proof of a human result or unchanged real-time simulation. Avoid recursively calling render from a render callback.
5. Encode a short complete cycle first; compare adjacent frames across its boundary, inspect motion and listen to sound joins. Repeat only that verified source, make a separately licensed continuous soundtrack, then fully decode the final long file. Check encoded duration/frame count, loudness/true peak, and representative joins/endpoints. Keep sampled inspection, listening and owner acceptance distinct.

## Deliver and retain

Provide the MP4, separate cover and plain-text publication copy with source/attribution, the published game link and a clear repeated-cycle disclosure. Add SRT only when there is speech. Use the existing project journal and file pins; do not create a second competing lifecycle. A public video link is a later owner-report publication receipt, not an automatic creative/listening pass.

The current proof covers one 1080p30 Babylon/browser recording and FFmpeg assembly. It does not establish mobile recording, arbitrary worlds, seamless procedural audio, an automatic genre-aware reviewer or a new runtime planner provider. Capture failures and service advice stay linked to the case rather than being erased by the final export.
