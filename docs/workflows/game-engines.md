# Games, engines and video production

Framewright treats game engines as both subjects and production tools. Books and
software promos were initial cases; they do not limit the studio's subject matter.

| Direction | Intended result | What needs its own test |
| --- | --- | --- |
| Create a game | Playable miniature game, coherent controls, music and endings | Input clarity, character/action consistency, both outcomes, audio and actual playability |
| Review a game or engine | Narrated walkthrough with real gameplay or service UI | Recorded functions, capture quality, truthful commentary and reproducible demonstrations |
| Use an engine as a virtual set | Original story, scene, interior or action captured for an unrelated film | World/character continuity, camera control, repeatable takes, export/capture, sound and montage seams |

## Reusable production contract

1. Choose the direction and bounded deliverable before selecting an engine.
   Record engine/build identity, required services, resource budget and controls.
2. Record rights separately for engine code, game/mod content, characters, music,
   footage and generated assets. A service account or engine licence does not
   itself clear all scene content. Preserve private reference files outside Git.
3. Test the selected capability: game playability; review demonstrations; or
   repeatable world/camera/action takes. Retain failures as well as successes.
4. Capture the real running build. Record its revision, input method, time ranges,
   audio source and capture method. Label scripted demonstrations as scripted;
   authored reconstruction is not captured gameplay. Inspect both endings when
   the film promises both. A generated character clip is not a gameplay export.
5. Assemble the film with separately checked narration, game audio/music,
   captions, title and thumbnail. Verify final decode, sync, listening and sampled
   frames. Keep game hosting, feed publication, local video delivery and YouTube
   publication as separate states; store owner-supplied URLs with that provenance.

The [agent skill](../../skills/game-engine-production/SKILL.md) routes these modes.
This is a manual workflow, not a new automatic provider in the planning router.

## Tested game-to-video adapter

The first case records actual local rev12 Canvas frames and the final game-audio
bus into one MediaRecorder,with scripted input/state logs for both outcomes. It
uses MoviePy static title/thumbnail composition and FFmpeg footage assembly,then
external pinned Supertonic narration and final-file QA. See the
[film record](../../experiments/2026-10-17/disco-coffee-game-overview.md) for limits and failures.
This proves this exact game-overview chain;it does not yet prove recording other
engines,reviewing every PlayMCP function or staging unrelated stories.

trial:manual portrait framing,comic narration and encoded opening-frame covers.
