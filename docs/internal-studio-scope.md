## Planned expansion — no activation now

Owner clarified that this broader direction belongs in the roadmap. Do not treat it as work to implement all at once or as current automatic publishing. Progress through separately agreed slices: prove manual platform-specific output → stabilise a reusable template → transfer it to the receiving project → test generation and approved delivery → only then consider explicitly authorised publication automation and observation. SSI has its own existing configured trial; this note changes none of it. AzurMenton first needs its template/approach refined; Instagram/Facebook/personal-account operation is later. No new schedule, standing account permission or fixed date is created.

## One shared production contract

Use the existing brief/source/claim/decision/rights/output records for all directions. At intake identify intended product, audience/language, platforms, dimensions/duration, available sources, review steps and receiving project. Select tools by the actual job and machine/budget; new research is not a new capability. Preserve one canonical production journal and the receiving project's responsibility.

Do not add a second task system, publisher, growth agent or cross-project scheduler. Each public action/account change needs existing applicable authority; no promise of views or monetisation follows from packaging. Reuse stable recipes and measure actual revisions/time/resources before claiming faster or cheaper production. M4 covers controlled tool expansion, SOCIAL-01 covers platform packaging and M6/REL-D covers real transfer.
