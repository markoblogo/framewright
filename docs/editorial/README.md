# Framewright Studio Notes — weekly English blog drafts

Owner-authorised26October2026: prepare one English blog article weekly, with ABVX
metadata, a generated cover image and1–3 relevant YouTube videos reported published by the owner. First draft:
[Studio Notes01](2026-10-26-framewright-studio-notes-01.md).

Default cadence: **Monday10:00 Europe/Paris**, starting2November2026 after the first
manual26October edition. The Codex thread heartbeat owns scheduling; this folder is
an editorial record, not a second cron service. If local access is unavailable,
report that condition without creating replacement journals elsewhere.

## Every edition

1. Read the current README, selected new experiment records, source-pinned journal/
   evidence and changes since the prior edition. Include local development honestly;
   a local helper, merged commit and released feature are distinct states.
2. Choose a coherent practical theme. Explain what changed, why it matters, an actual
   example, limitations and the next proof. Target roughly600–1000 words where useful;
   do not pad. Use first-person English and clear links; avoid unsupported time savings,
   audience gains, universal compatibility or unobserved human approval.
3. Include1–3 relevant YouTube examples. Record each case source, URL, publication
   provenance and access outcome. An inaccessible fetch is not evidence of removal;
   an owner-supplied URL is not independent visibility/uploaded-byte verification.
   Reused earlier videos are allowed when clearly described as earlier examples.
4. Save a dated Markdown file with the complete ABVX block: SEO title, Slug, Meta
   description, Excerpt, Collection, Content type, Language=en, Primary topic tags,
   Additional tags for Book Readiness Radar. Working series/collection:
   **Framewright Studio Notes**; CMS collection existence is not verified. Do not
   create a CMS collection or silently substitute a different one.
5. Generate a required landscape cover with the built-in imagegen tool: original
   editorial composition, exact English headline and series/issue label, readable
   at full size and reduced width. Keep it separate from video thumbnails. Supply
   the actual PNG/JPEG, descriptive English alt text, file dimensions/hash and prompt/
   provenance; record review and any known cost separately. A concept prompt alone
   does not complete the cover. Keep media in the private publication workspace,
   outside Git; retain only text evidence here. Use the restrained charcoal/teal/amber
   visual family for continuity when appropriate. No third-party reference upload
   or chargeable CLI/API fallback without separate authority. If image generation
   is unavailable, mark the edition incomplete and report the cover blocker.

   Retain a companion source receipt and append the edition to `series.json`, with
   draft/cover hashes, source hashes, covered capabilities and publication state. Review
   [BOOK-01](../book-milestone.md); report newly satisfied gates, not article counts
   as readiness. Validate local links, metadata,1–3 videos and the actual cover file.
   Include `Cover file` and `Cover alt` in the publication metadata.

Required handoff: English post, complete ABVX metadata,1–3 YouTube links, generated
cover file and alt text, source/cover receipt. Cover text accuracy and readability
are reviewed separately from owner approval and CMS publication.

The draft is a publication-ready text for owner review, not an automatically published
post. No CMS writes, email/messages to third parties, video/audio generation, paid API calls,
Git push or release. A blog URL is recorded only after supplied/observed publication.
If there is no substantive update, a sourced retrospective lesson may be useful;
if there is neither new material nor a useful lesson, do not manufacture an edition.
Keep unchanged/non-actionable scheduler runs quiet; notify on a new draft, a meaningful
book-readiness transition or an actionable failure.

## Publication links and book-source intake

The owner publishes the posts and supplies the resulting blog URLs afterwards.
Record each URL on its matching existing edition, with the date received and
`owner_provided_url` provenance. Preserve the prepared text/cover hashes and any
separately observed published revision. Until a URL arrives, the edition stays a
draft; afterwards record owner-reported publication, without claiming independent
visibility, uploaded-text equality or audience results. A later correction/removal
is another dated observation, not a silent rewrite of the earlier record.

Every edition is also candidate source material for the [method-first book](../book/README.md). Keep
useful explanations, worked cases, mistakes/corrections and links findable through
the same edition index; no parallel manuscript archive is required. Before chapter
reuse, verify facts, remove overlap, prepare parallel explanations with Framewright and without it, and resolve intended
quotation/illustration permissions. Link applicable chapters/cases/gaps in the same
[book index](../book/index.json); maintain working documentation, not manuscript chapters. Publication
does not automatically approve a chapter or demonstrate book readiness.

## Evidence and reuse

`series.json` is the issue index, with the last covered baseline and exact files.
Companion `*-sources.json` records freeze selected evidence without copying private
journals, email, full media, app files, paths or credentials into public prose/Git.
Quoted source material has separate permission; do not treat metadata tags or prior
YouTube publication as permission to reproduce third-party illustrations in the book.
Do not re-search the full tool catalogue each week merely to fill an article.
