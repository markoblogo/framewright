# Moving 3D explainers with bounded corrections

6 November 2026 · M3/M4, R04/R05/R09 · [worked case](../productions/github-agentic-workflows.md).
One owner-accepted film establishes this route on this host, not general tool qualification or measured savings.

## Build action around the explanation

1. Freeze the source claims, narration, intended audience and one visual metaphor. Show a short pilot before expanding. This case used an ivory miniature workshop, navy machinery and restrained vermilion/yellow accents.
2. Measure cached speech and derive scene boundaries in frames. Keep titles and supporting text large and high in the composition. Separate explanatory diagrams from real application footage and measured data.
3. Give each long sentence a sequence of visible actions. Documents pass a packet; resource modules open while tokens travel; evidence cards accompany an illustrative range; a task advances through a gate into a proposal tray. A slow orbit around an otherwise frozen diagram did not satisfy the owner.
4. Keep geometry and labels legible throughout movement. Check object contact, gate clearance and moving shapes against the title area, not just text bounding boxes. Camera motion alone does not prove meaningful action.
5. Encode independent scene clips, assemble them with the retained mix and review the actual movie. A successful decode is separate from creative and listening acceptance.

The figures illustrate stages, not numerical cost shares or a real forecast. Do not animate invented measurements to make a shot more exciting.

## Correct only the affected part

Record the interval, desired change and invariants first. In this case scenes 1/4/5/7 changed; scenes 0/2/3/6, measured voice stems, final mix and subtitles were retained and hash-checked.

- Pin scene source, CSS, timeline, runtime versions, capture settings and encoded clip hashes. Check both dependencies and output bytes before cache reuse. File existence alone can admit a partial or stale render.
- A shared source edit invalidates the global source fingerprint. Reuse unaffected clips only after an explicit impact assessment; this case's manual four-scene scope is not automatic semantic dependency analysis.
- Use one frame-boundary rounding rule everywhere. JavaScript rounds positive half frames upward; Python's default `round` does not always match it. Use an explicit equivalent when comparing frame counts.
- The final clip ends at the **film duration**, including its quiet/fade tail, rather than the last speech scene's end. The first correction capture omitted 38 tail frames; the frame-count check caught it before delivery and the ending was recaptured.
- Preserve the accepted movie during correction. Reassemble, fully decode, check duration/frame count, inspect the affected joins and obtain a new exact-version decision.

The retained route used StageShow's virtual clock with forward advance and priming before each selected range. Arbitrary backward seeking of the renderer was not qualified. Seeking an encoded MP4 is a different operation.

## Review a seekable movie

Use the standard [local preview server](../../skills/video-production-router/references/preview.md), not a bare server that ignores byte ranges. Prepare MP4 with `+faststart`. Test native timeline movement forward/backward before watching the whole movie; chapter buttons are a convenience, not a substitute for that check.

Keep one browser-readable publication page with direct video, cover and subtitle links and copyable text. Retain the final master locally after the owner supplies a publication URL.

## With Framewright / without it

**With Framewright:** retain source pins and decisions in the existing project journal; select the accepted exact final. Use the source/clip checks and explicit correction scope above. Owner publication receipts and the optional Radar adapter preserve provenance; neither implies analytics or permission to publish another film.

**Without Framewright:** keep the same brief, claim list, measured voice table, frame-based shot plan, source/version manifest and review decisions in a folder. Render the scene clips in a chosen 3D/compositing tool, assemble with FFmpeg or an editor, and maintain a simple hash manifest for unchanged clips. Serve the review folder with a byte-range-capable localhost server. This alternative is a written portable process, not an independently reproduced production.

## Limits and useful next checks

StageShow commit `299140fafd08df55a9c234e610c3f64af3f45531` (MIT), React 18.3.1, Vite 6.4.5 and Three.js 0.180.0 were used in this production. Default headless WebGL failed; software SwiftShader with explicit flags worked. Initial full-picture capture took 964.351 seconds on this host; active operator work, correction totals and subscription allocation were not measured. No speed/cost savings claim follows.

Three.js r187, automatic page-to-scene conversion, arbitrary renderer reseeking, articulated character animation and a second independent reproduction remain untested here. The SRT splits are estimated within measured phrases, not forced-aligned word timings. Future trials should address a real next-production weakness rather than reopen the whole tool queue.
