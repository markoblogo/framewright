# Illustrative media-search explainer

A bounded R04/R09 / SOURCE-01 presentation recipe from [EmbeddingGemma 2](../productions/media-semantic-search.md), 6 November 2026. The film explains retrieval; it does not qualify an embedding model or a semantic-search implementation.

## Repeatable recipe

1. Freeze a concrete archive question and its failure case. Here: a bird kicking a gate versus a bird merely running. Read primary sources, then agree the script and donor ranges before assembly. Keep the model's capability claims separate from what the studio actually runs.
2. Reuse six short permitted ranges from retained original productions. Record original file, start/duration and provenance. Make silent low-resolution proxies for boards/pilot; strip donor sound. Preserve the original masters for the full-resolution composition. Never index the whole personal archive as an incidental step.
3. Build a moving contact sheet, query, selected excerpt and source time range. Reuse one coherent cream/black/yellow graphic system. Put film-name and example-purpose pills on every visible donor, near its upper edge. The result ranking/time ranges are authored illustrations, labelled as such; do not add fake model scores.
4. Measure narration phrases, then derive the scene lengths. Keep cards and donor action moving while the explanation unfolds. Use a separate near-match scene to explain why similarity is not certainty. Full assembly uses native 1920×1080 graphics; the fictional ostrich source remains 1280×720.
5. Review the encoded pilot, then the full film with sound. Retain full decode, dimensions/frame rate, representative encoded scene samples, audio checks and native forward/backward seeking on the range-enabled preview server. Caption chunks use proportional phrase timing, requiring a separate sync/readability review when precision matters.
6. Freeze the accepted master and deliver direct MP4/JPG/SRT links plus one browser-readable copy document. Record the owner's publication URL separately from uploaded-file identity, public visibility and metrics. Link the exact Radar card and return the pinned status; repeated delivery must not create a second project/video mapping.

## With and without Framewright

With Framewright: retain the schema2 project journal, input/output hashes, exact-version acceptance, source manifest, publication receipt and optional Radar association. Keep private footage, research captures and provider assets outside Git. Use the existing range-enabled preview server rather than a new per-film server implementation.

Without Framewright: keep the brief, source/range manifest, script/voice timings, editable composition, accepted output hash, review notes, delivery files and publication URL in one folder. Use a local compositor/FFmpeg and an HTTP server supporting byte ranges. Track an editorial recommendation ID manually if needed. This alternative is guidance, not an independently completed reproduction.

## Limits and next fitting test

- No EmbeddingGemma inference, embeddings, actual ranking, library index or benchmark was run. The success is an accepted explanation using authored results, not model evaluation.
- Cropping/scaling donor footage preserves aspect but does not recover missing detail. A previous publication is not blanket permission for arbitrary third-party reuse; retain each source's applicable rights.
- The original soundtrack and local Supertonic narration replace donor audio. Existing clip labels, voice-output terms and the new cover's provenance remain retained privately; cover use/CTR are not independently observed.
- Motion graphics are authored, not automatic video understanding. Source/use labels are part of this accepted design; tiny labels are supplementary and must not carry the main explanation.
- The original Radar card was attached after production as retrospective_observation. Transport/duplicate checks do not backdate a prospective experiment, acquire metrics or complete REL-D/M6.
- A future SOURCE-01 trial may index a small cleared library and retain real queries, source ranges and one retrieval failure after resource/licence admission. It remains unexecuted; this recipe does not start a download or trial.
